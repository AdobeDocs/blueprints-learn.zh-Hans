# 创建排名公式

## 目标

现在，所有选件项目都已创建、划分优先级、应用资格并组织到集合中，我们可以关注确定它们在给定用户档案中的排名。 可通过创建排名公式来实现这一点。

排名公式会根据与Web/移动属性或体验事件本身交互的用户档案中的条件，动态提升特定优惠的优先级，以使它们“跃升至顶部”。

在本实验场景中，我们将假定Connection 5G的研究营销团队显示，年龄在39岁以下的人将被吸引到Ultra或Pro层，而40-59岁的人将被吸引到基本层和专业层。 由于Connection 5G宁愿销售更高端的手机，在所有条件都相同的情况下，超级机型将首先针对39岁以下的人呈现，而专业机型将首先针对40至59岁的人呈现。 本节将向您展示如何创建排名公式以满足这些业务要求。

## 创建排名公式和默认表达式

1. 如有必要，请在左边栏中展开&#x200B;**决策**，然后单击&#x200B;**策略设置**。 您登录至“决策规则”页面，并查看您之前创建并用作上层电话优惠项目的资格要求的“上层计划”决策规则。
2. 单击“排名方法”菜单下的&#x200B;**排名公式**。 这将打开一个空页面，因为您还没有任何排名公式。

   创建公式前![清空排名公式页面](assets/create-ranking-formula-empty-ranking-formulas-page.png)

3. 单击蓝色的&#x200B;**创建公式**&#x200B;按钮开始创建新的排名公式
4. 命名排名公式&#x200B;**iPhone 17排名公式**

   >[!NOTE]
   >
   >当使用从活动的决策包请求选件所需的参数将体验事件发送到Edge数据收集时，该包中的所有选件都使用排名公式进行计算。 每个选件都将保持其原始优先级，或根据触发体验事件的用户档案动态调整其优先级。

5. 滚动到“标准”部分的底部，单击最底部文本框的&#x200B;**\&lt;/>**&#x200B;图标，然后选择&#x200B;**优惠优先级得分**&#x200B;变量。

![在排名公式条件中选择的优惠优先级得分变量](assets/create-ranking-formula-select-offer-priority-score.png)

默认表达式现在设置如下：

![设置为优惠优先级得分变量的默认表达式](assets/create-ranking-formula-default-expression-set.png)

>[!NOTE]
>
>此底部文本框是应用于任何不符合任何优先级调整标准的选件项的默认表达式。 在这种情况下，这仅仅是创建选件时分配给该选件的优先级。 如果没有为将执行此排名公式的集合指定默认优先级分数，则您需要分配默认分数

## 创建优先级调整规则

现在，有了默认表达式，您可以开始添加规则，以根据用户年龄动态调整优先级。

考虑优先级调整规则的一种方式是将它们视为仅应用于特定优惠的标准if/then语句。 如果测试证明是正确的，则调整满足给定标准的优惠的优先级。 UI会按照稍微不同的顺序排列这些内容，正如此屏幕快照中所说的那样。

优先级调整规则中if、then和where节的![UI顺序](assets/create-ranking-formula-if-then-where-rule-order.png "优先级调整规则中if、then和where节的UI顺序")

>[!NOTE]
>
>“if”是可选的，因为可以在优惠满足特定标准时应用优先级调整规则，而无需先使用条件语句。 扩展本指南中的示例，假设我们提供了多个具有手机操作系统属性的选件（Android与iOS）。 如果个人资料的首选操作系统是iOS，则可以提升所有iPhone选件的优先级。 没有“如果”。 只需“调整分数，其中优惠属性=配置文件属性”。 下图与上述图像相似，它概述了这一想法，但没有条件语句。
>
>![在没有条件if语句的情况下应用了优先级调整规则](assets/create-ranking-formula-rule-without-conditional.png "在没有条件if语句的情况下应用了优先级调整规则")

## 创建标准1：适用于39岁以下青年的调整规则

1. 首先创建Ultra层选件项的排名规则。 单击&#x200B;**标准1**&#x200B;部分中的第一个文本框，然后在其出现时单击&#x200B;**选择属性**&#x200B;按钮。

   ![为条件1](assets/create-ranking-formula-criterion-one-select-attribute.png)选择显示的属性选项

2. 当“选择属性”对话框打开时，单击&#x200B;**选件名称**。 选择后，单击&#x200B;**保存。**

   >[!NOTE]
   >
   >“决策属性”是指优惠项目的元素。 由于这是您概述标准将应用于哪个选件项目的位置，因此您可用的唯一选项是选件项目的属性。
   >

3. 将运算符保留设置为“等于”，在剩余的文本框中，输入ultra tier选件项的名称，即&#x200B;**iphone：17\：ultra**。 输入文本后，UI将更新并反映匹配条件已被接受。
4. 单击&#x200B;**+添加条件**，然后单击显示的&#x200B;**新文本框** (其中包含文本“*单击以创建决策项……*”
5. 单击现在可用的&#x200B;**选择属性**&#x200B;选项**.**
6. 当“选择属性”对话框打开时，单击&#x200B;**配置文件属性>人员**（您可能需要向下滚动）**>出生年份**。 选择后，单击&#x200B;**保存。**

   >[!NOTE]
   >
   > “配置文件属性”是指发送体验事件的用户或配置文件，“上下文数据”是指体验事件本身中的元素，例如URL、页面名称或体验事件有效负载的其他属性。

7. 将运算符更改为&#x200B;**大于**&#x200B;并输入出生年份&#x200B;**1986**（UI在年份中放入逗号，这是预期的）。 进入后，UI会更新以反映条件已被接受。 由于商业使用案例是向40岁以下的人提供Ultra Tier，因此优先顺序将调整为1986年以后出生的人。

   >[!NOTE]
   >
   >如前所述，UI指示这些附加条件是“可选的”。 这是真的，因为用户可能希望无需任何其他条件即可动态调整优惠项目集的优先级。 相同选件项目可能用在不同的收藏集中并按不同的排名规则集进行排名。 由于本实验仅使用一组选件项目，因此会使用其他条件来调整优先级。

8. Ultra层选件项的原始优先级为4。 要提高优先级，请将其乘以100。 为此，请单击最后一个文本框旁边的&#x200B;**\&lt;/>**&#x200B;图标，然后选择&#x200B;**优惠优先级得分**&#x200B;变量。 在自动输入的文本后添加&#x200B;**\*100**。 此表达式将原始优先级(4)乘以100，并赋予其新优先级400。

   现在，您的规则应如下所示：

![标准1规则将Ultra层优惠优先级分数提升100](assets/create-ranking-formula-criterion-one-ultra-boost.png)

>[!NOTE]
>
>为什么要乘以100？ 这个想法是，如果你想要确保你的优先顺序调整得远远高于其他优先顺序，100只是通过简单的数学计算来实现这个目的。 排名公式可能会很复杂，您将在下一节中看到，因此保持简单的数学计算会很有帮助。
>
>此外，当我们使用乘法来提高优先级分数时，其他数学表达式也可以用来降低优先级分数。 但是，一般而言，使所需选件“浮到顶部”比使选件不想“沉到底部”更容易。



## 创建标准2：适用于40-59的调整规则

1. 在刚刚创建的调整规则正下方，单击&#x200B;**+添加条件**&#x200B;按钮。
2. 创建&#x200B;**选件名称**&#x200B;不等于&#x200B;**iphone：17\：ultra**&#x200B;的匹配条件。

   >[!WARNING]
   >
   >此规则旨在应用于所有其他选件项目。 有关原因的更多详细信息将在此页面上进一步介绍，但在实际应用中使用此类逻辑时应非常谨慎，因为它将应用于集合中不具有此值的每个选件。 在我们的用例中，这没有问题，但在其他用例中可能不会。

3. 添加此规则应应用于出生年份大于&#x200B;**1966**&#x200B;的任何人（60岁以下的任何人）的条件。
4. 与上一规则一样，将选件项目的默认优先级分数乘以100。 完成后，您的“标准2”规则将如下所示：

![标准2规则调整1966年之后出生的用户档案的优先级](assets/create-ranking-formula-criterion-two-rule.png)

>[!NOTE]
>
>将排名公式和资格规则结合使用可能会让人觉得很复杂，但核心思想是：
>
>- **排名公式**&#x200B;动态调整优先级分数，从而调整优惠的顺序。
>- **资格规则**（如决策规则和频率上限）可在用户无权查看选件时，从排序列表中删除这些选件。
>
>以下是在这些示例以及您刚刚创建的排名公式的基础上对选件排序的方式：
>
>**出生年份= 1990**
>
>- 超优先级变为&#x200B;**400**
>- Pro = **3**，Base = **2**，Generic = **1**
>  结果：Ultra首先显示（最多3次），然后显示Pro、Base，最后显示Generic。
>
>**出生年份= 1970**
>
>- 超优先级保持在&#x200B;**4**
>- Pro变为&#x200B;**300**，基数= **200**，通用= **100**
>  结果：Pro首先显示（3次），然后依次显示“基础”和“类属”。 Ultra最后排序，因为其优先级(4)低于通用(100)。
>
>通过决策规则和频率上限应用资格时，则
>
>- 1990年出生且计划ID = 1 **的用户将删除Ultra和Pro选件，即使它们排在最高位。**&#x200B;用户只能看到Base和Generic选件，因为Ultra和Pro层有一个附加条件：只有具有&#x200B;**计划ID 2或3**&#x200B;的用户才能看到它们。
>- 由于通用选件没有频率上限规则，因此&#x200B;**1970**&#x200B;出生年份用户将永远不会看到Ultra选件，因为其优先级分数低于通用选件的提升分数。

5. 设置好所有规则和默认优先级分数后，向后滚动到顶部，然后单击右上角的蓝色&#x200B;**创建**&#x200B;按钮。

>[!TIP]
>
>现在，您将返回“策略设置”页面，并看到刚刚创建的单个排名公式。

>[!NOTE]
>
>如果两个选件产生了相同的优先级，会发生什么情况？ 具有相同优先级得分的选件是随机选择的，以返回到请求系统。

## 回顾

在此页面中，您构建了一个排名公式，用于确定如何为每个用户档案动态排序选件项目。 您还可以定义默认表达式（原始优先级分数），然后添加优先级调整规则，以根据用户档案条件（如年龄）提升选件优先级。 此排名逻辑可确保相关选件（如特定年龄范围的Ultra或Pro层）在评估时排名最高。
