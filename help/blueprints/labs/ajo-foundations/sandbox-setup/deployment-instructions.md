# 部署说明

>[!WARNING]
>
>只有在您按照自己的进度在实验室中工作时，才需要使用此功能。 如果您正在参加实时培训课程或活动，则已为您部署了沙盒。

AJO架构基础实验室包是使用DEP CLI部署到沙盒中的，CLI是一种命令行工具，用于创建将在整个实验室中使用的架构、数据集、数据流和示例数据，包括用于编排营销活动的配置文件存储和AJO关系存储。

## 部署内容

**个人资料曲目**

- 身份命名空间(customerID、planID、productID)
- 为配置文件启用的标准XDM字段组、描述符和架构
- 为配置文件启用的目录数据集
- 合并策略和受众
- 以下三个示例数据集的配置文件数据：深度模式（特征+事件）、陌生人事物（特征）和决策（特征）

**关系跟踪**

- customerID身份命名空间
- 11个带主键、外键和版本描述符的关系XDM架构
- 为AJO编排的活动启用11个数据集
- 11个数据流从数据登陆区加载数据

>[!NOTE]
>
>端到端部署大约需要2小时23分钟。 配置文件和关系型跟踪并行运行，并且大部分时间是CLI自动执行的无人值守等待时间。

## 先决条件

- **许可证授权。** 使用Real-Time CDP（含流分段）和Adobe Journey Optimizer（含编排的营销活动）的IMS组织的管理权限
- **访问权限。** 具有Target沙盒上所有权限的Experience Platform角色，包括您从[Developer Console设置](developer-console-setup.md)创建的API凭据。
- **Developer Console凭据。** 包含Adobe Experience Platform API和Adobe Journey Optimizer API的项目。 如果您还没有这些设置，请先执行[Developer Console设置](developer-console-setup.md)
- **沙盒。** 为空，类型为`dev`，且处于“就绪”状态至少120分钟，然后才能开始部署
- **Node.js.** 任何最新的LTS版本，在Windows或Mac上

## &#x200B;1. 安装CLI

1. 克隆或下载[dep-cli存储库](https://github.com/adobe/dep-cli)
1. 从`dep-cli`目录，运行`npm install`
1. 使用`npm start`启动CLI

>[!NOTE]
>
>运行上述命令之前需要Node.js。 如果尚未安装Node.js，请首先查看Wiki的[Node.js设置](https://github.com/adobe/dep-cli/wiki/Nodejs-Setup)页。 有关完整安装详细信息（包括屏幕截图以及如何更新现有安装），请参阅[安装](https://github.com/adobe/dep-cli/wiki/Installation)Wiki页面

## &#x200B;2. 配置环境文件

CLI将部署到您的环境文件指向的任何沙盒，因此必须在运行任何内容之前正确设置此沙盒。

1. 复制`envFiles/sample-env.json`并为其提供一个新名称，如`my-env.json`
2. 打开文件并使用[Developer Console设置](developer-console-setup.md)中的值填写以下字段：

   | **字段** | **值** |
   | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `API_KEY` | 客户端ID |
   | `CLIENT_SECRET` | 客户端密码 |
   | `IMS_ORG` | 组织ID |
   | `SCOPES` | 必须包括Experience Platform API和Adobe Journey Optimizer API范围&#x200B;<br />*（例如cjm.suppression\_service.client.delete、cjm.suppression\_service.client.all、openid、session、AdobeID、read\_organizations、additional\_info.projectedProductContext）* |
   | `SANDBOX_NAME` | 您定位的沙盒 — 必须为空，且类型为`dev` |

3. 保存并关闭文件

>[!NOTE]
>
>每次运行CLI命令时，系统都会提示您输入此文件的名称，这样您便可以在下面的每个步骤中重复使用它。

## &#x200B;3. 运行AJO的“架构基础”菜单

从主菜单中，选择&#x200B;**AJO arch foundation**。 有两条跑道分成六步。

### 配置文件跟踪（按顺序运行）

>[!WARNING]
>
>在运行步骤1之前，沙盒必须处于“就绪”状态至少60分钟。

| **步骤** | **它的功能** | **运行它之前** |
| ------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------- |
| &#x200B;1. 创建基本配置文件 | 部署身份命名空间、架构、数据集、合并策略和受众 | 沙盒“就绪”持续60分钟以上 |
| &#x200B;2. 加载配置文件数据 | 创建数据流和流式传输深度模式、陌生事物和决策用户档案数据 | 步骤1后等待60分钟以上 |
| &#x200B;3. 检查配置文件运行状况 | 验证所有配置文件数据是否正确加载 | 步骤2后等待15分钟以上 |

步骤1大约需要2分钟，步骤2大约需要6分钟。

>[!NOTE]
>
>如果出现问题，步骤2可安全重新运行 — 它会覆盖现有特征并跳过重复事件。

### 关系跟踪

>[!WARNING]
>
>在运行步骤4或步骤6之前，沙盒必须处于“就绪”状态至少120分钟。

| **步骤** | **它的功能** | **运行它之前** |
| ----------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------- |
| &#x200B;4. 创建关系型数据库 | 创建customerID命名空间和关系架构/描述符/数据集 | 沙盒“就绪”持续120分钟以上 |
| &#x200B;5. 加载关系数据 | 上传11个CSV文件并创建加载这些文件的数据流 | 在步骤4之后立即运行 — 无需手动等待 |
| &#x200B;6. 部署关系型基础和数据 | 将步骤4和步骤5合并为一次约5分钟的运行 | 沙盒“就绪”持续120分钟以上 |

>[!NOTE]
>
>使用步骤6，而不是分别运行步骤4和5 — 它一次执行相同的操作，为您处理传播等待。

>[!NOTE]
>
>上述所有等待时间均由CLI自动检查。 如果您过早执行步骤，它会阻止您执行操作，并告诉您需要等待多长时间。

## 故障排除

>[!WARNING]
>
>**配置文件运行状况检查因缺少事件而失败。** 某些配置文件数据尚未完成传播。 再等待15分钟，然后重新运行检查配置文件运行状况。 如果仍然失败，请重新运行加载配置文件数据，等待15分钟，然后再次检查。

>[!WARNING]
>
>**关系数据加载在中途失败。** 每个API调用最多重试3次。 如果仍然失败，清理会删除它创建的源连接、目标连接和数据流，以便您可以干净地重新运行步骤5（或步骤6）。 映射集无法通过API删除，并且可能被留下 — 这不会影响重新部署。

**有其他错误。** 作为最后手段，您可以从CLI的沙盒管理菜单中重置沙盒，并从步骤1中重新部署。

>[!CAUTION]
>
>重置沙盒具有破坏性。 CLI要求您在继续之前键入要确认的沙盒名称。
