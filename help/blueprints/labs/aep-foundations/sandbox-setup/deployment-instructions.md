# 部署说明

> [!NOTE]
>
>只有在您按照自己的进度在实验室中工作时，才需要使用此功能。 如果您正在参加实时培训课程或活动，则已为您部署了沙盒。

AEP Foundation实验室包是使用DEP CLI部署到沙盒中的，CLI是一个命令行工具，用于创建将在整个实验室中使用的架构、数据集、数据流和示例数据。

## 部署内容

- 4个身份命名空间
- 1个架构类、13个字段组、10个架构
- 12个身份描述符、6个关系/引用描述符、3个友好名称描述符
- 10个目录数据集
- 1个HTTP API源连接和10个数据流
- 配置文件数据：一个深度模式配置文件（3个特征数据集、7个事件数据集）加3个查找数据集
- 2个配置文件合并策略和1个受众（任何事件流，一小时内）

>[!NOTE]
>
>端到端部署大约需要2小时24分钟，其中大多数步骤之间的无人值守等待时间。 CLI会自动强制执行这些等待，因此您无需自行安排任何时间。

## 先决条件

- **许可证授权。** 使用Real-Time CDP的IMS组织的管理权限（包含流式分段）
- **访问权限。** 具有Target沙盒上所有权限的Adobe Experience Platform角色，包括您从[Developer Console安装程序](developer-console-setup.md)创建的API凭据。
- **Developer Console凭据。** 包含Adobe Experience Platform API的项目。 如果您还没有这些设置，请首先遵循[Developer Console设置](developer-console-setup.md)
- **沙盒。** 为空，类型为`dev`，且处于“就绪”状态至少60分钟，然后才能开始部署
- **Node.js.** 任何最新的LTS版本，在Windows或Mac上

## &#x200B;1. 安装CLI

1. 克隆或下载[dep-cli存储库](https://github.com/adobe/dep-cli)
1. 从`dep-cli`目录，运行`npm install`
1. 使用`npm start`启动CLI

>[!NOTE]
>
>运行上述命令之前需要Node.js。 如果尚未安装Node.js，请首先查看Wiki的[Node.js设置](https://github.com/adobe/dep-cli/wiki/Nodejs-Setup)页。 有关完整安装详细信息（包括屏幕截图以及如何更新现有安装），请参阅[安装](https://github.com/adobe/dep-cli/wiki/Installation)Wiki页面

## &#x200B;2. 配置环境文件

CLI将部署到您的环境文件指向的任何沙盒，因此必须在运行任何内容之前正确设置此沙盒。

1. 复制`envFiles/sample-env.json`并为其提供一个新名称，如`my-env.json`
2. 打开文件并使用[Developer Console设置](developer-console-setup.md)中的值填写以下字段：

| **字段** | **值** |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `API_KEY` | 客户端ID |
| `CLIENT_SECRET` | 客户端密码 |
| `IMS_ORG` | 组织ID |
| `SCOPES` | 必须包括Experience Platform API范围(openid、session、AdobeID、read_organizations、additional_info.projectedProductContext) |
| `SANDBOX_NAME` | 您定位的沙盒 — 必须为空，且类型为`dev` |

3. 保存并关闭文件

>[!NOTE]
>
>每次运行CLI命令时，系统都会提示您输入此文件的名称，这样您便可以在下面的每个步骤中重复使用它。

## &#x200B;3. 运行AEP基础菜单

从主菜单中选择&#x200B;**AEP基础**。 有三个步骤，它们必须按顺序运行。

>[!WARNING]
>
>在运行步骤1之前，沙盒必须处于“就绪”状态至少60分钟。

| **步骤** | **它的功能** | **运行它之前** |
| ----------------------- | ------------------------------------------------------------------------------------------ | ------------------------------- |
| &#x200B;1. 创建基本配置文件 | 部署身份命名空间、架构、数据集、合并策略和受众 | 沙盒“就绪”持续60分钟以上 |
| &#x200B;2. 加载配置文件数据 | 创建数据流和流配置文件和查找数据 | 步骤1后等待60分钟以上 |
| &#x200B;3. 检查配置文件运行状况 | 验证所有数据是否已正确加载 | 步骤2后等待15分钟以上 |

步骤1大约需要2分钟才能运行，步骤2大约需要6分钟，步骤3是一个快速验证步骤，无需等待本身。 两个步骤之间相距60到15分钟的间隔可让AEP在幕后完成数据传播 — 这是您2小时时间线中的大部分时间。

> [!NOTE]
>
>CLI会自动检查这些等待时间。 如果你过早跑步，它会阻塞，告诉你还有多少分钟 — 你不需要自己追踪时钟。

>[!NOTE]
>
>如果出现问题，可以安全地重新运行步骤2。 它会覆盖现有特征记录并跳过重复事件。

## 故障排除

>[!WARNING]
>
>**运行状况检查失败，缺少事件**。 某些配置文件数据尚未完成传播。 再等待15分钟，然后重新运行检查配置文件运行状况。 如果仍然失败，请重新运行加载配置文件数据，等待15分钟，然后再次检查。

**有其他错误。** 作为最后手段，您可以从CLI的沙盒管理菜单中重置沙盒，并从步骤1中重新部署。

>[!CAUTION]
>
>重置沙盒具有破坏性。 CLI要求您在继续之前键入要确认的沙盒名称。
